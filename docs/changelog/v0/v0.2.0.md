# lib-otp v0.2.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/0.2.0`

---

## Overview

v0.2.0 moves `renderQr` to its own subpath, `@cldmv/lib-otp/qr`, so the main entry no longer loads `qrcode`. A host that bundles the library into a single ES module could not load it before: gh-broker v0.11.0's daemon crashed at startup because the bundled `qrcode` (CommonJS) calls `require("fs")`.

---

## 💥 Breaking Changes

### `renderQr` is only on `@cldmv/lib-otp/qr` ([#11](https://github.com/CLDMV/lib-otp/pull/11))

The main entry no longer exports `renderQr`. Import it from the subpath instead:

```js
import { renderQr } from "@cldmv/lib-otp/qr";
```

It works the same as before. Everything else stays on the main entry. `dist/qr.mjs` imports `OtpError` from the main entry, so `renderQr` throws the same `OtpError` class the main entry exports.

Fixes [#10](https://github.com/CLDMV/lib-otp/issues/10).

---

## 🔧 CI & tooling

- `npm run build` now loads the built `dist/index.mjs`, `dist/index.cjs` and `dist/qr.mjs` once, and fails if the main entry imports `qrcode` again or `renderQr` throws a different `OtpError` class ([#11](https://github.com/CLDMV/lib-otp/pull/11)). Every unit test runs against `src/`, so nothing used to load the built files before publish.
