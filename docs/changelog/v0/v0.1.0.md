# lib-otp v0.1.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor (first release)
**Branch**: `release/0.1.0`

---

## Overview

First release of `@cldmv/lib-otp`: configurable TOTP codes, otpauth/QR enrolment and a pure per-person lockout state machine, plus an `otp` command line. It takes over the OTP gate logic that lived inside `@cldmv/gh-broker` and makes every part of it configurable, so gh-broker and Quack can share one implementation with their own policies.

The library is plain functions over injected inputs. It reads no environment, filesystem or clock (every call takes `now`) and keeps no module state. The host owns storage. Results are JSON-safe, and every deliberate rejection is an `OtpError` with a stable `code`.

## ✨ Features

### TOTP verification, enrolment helpers and the per-person lockout machine ([#6](https://github.com/CLDMV/lib-otp/pull/6), resolves [#2](https://github.com/CLDMV/lib-otp/issues/2))

- **TOTP and base32** (RFC 4226 / RFC 6238): `hotp`, `totpAt`, `stepAt`, `matchStep`, `safeEqual`, `base32Encode` and `base32Decode`.
- **One validated option set.** `parseOtpOptions` merges the input over `DEFAULTS`, rejects unknown keys and out-of-range values instead of clamping them, and returns a frozen config. Digits, period, skew, seed size, code reuse, the reuse window, failure counting, lockout length and escalation, and the hard lock are all configurable. The defaults are gh-broker's current values.
- **The lockout machine.** `stepOtp` is a pure reducer over one person's state, with the events `code-ok`, `code-bad`, `window-use`, `admin-unlock` and `tick`. It covers short lockouts with escalation, an optional hard lock after repeated lockouts, spent-code tracking (`spendThrough`) and a re-base of the spend marker when the period changes. `lockStatus`, `emptyPerson`, `isPersonState` and `compactPerson` round it out. Outcomes are reason codes, not prose.
- **Enrolment.** `newSeed` (at least 16 bytes), `otpauthUri`, `renderQr` (terminal, SVG or PNG, through `qrcode`), `verifyCode` and `currentCode`.
- **Status reporting.** `describeUser`, `describeUsers` and `formatStatus`.

### The `otp` command line ([#7](https://github.com/CLDMV/lib-otp/pull/7), resolves [#3](https://github.com/CLDMV/lib-otp/issues/3))

`otp seed`, `otp uri`, `otp qr`, `otp code` and `otp verify` over the library API.

- A seed is read from a file or stdin only, never from a command-line argument, and input is capped at 1 KiB. A seed file that is a symlink is refused, and one that group or other can read produces a warning.
- `otp qr --out <file>` creates the file exclusively with mode 0600. An existing file or symlink is refused unless `--force` is given.
- `--json` gives machine-readable output, and the exit codes are documented in the README.

## 🔧 CI & tooling

### The v4 release flow ([#4](https://github.com/CLDMV/lib-otp/pull/4), resolves [#1](https://github.com/CLDMV/lib-otp/issues/1))

The repo is on the CLDMV v4 workflow set, with lint and format configs, a precommit hook, `@cldmv/fix-headers`, a tsup `src` → `dist` build with a thin CJS shim, and the `@cldmv/vitest-runner` harness. The suite runs at 100% coverage. The package name follows the `lib-<thing>` rule for library repos.
